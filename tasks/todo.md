# DeckOS — قائمة المهام التنفيذية

> **المرجع المعماري:** `../integration-master-plan.md`  
> **أولوية التنفيذ:** `../lean-core-plan.md` — Lean Core أولًا، ثم الحزم.  
> **النطاق الحالي:** أول 90 يومًا (Phase 0 → Phase 1 Beta).  
> **قاعدة:** لا تُغلق مهمة بدون التحقق المذكور. لا ادعاء أداء بدون قياس. لا merge بدون CI.

> **ملاحظة:** هذه قائمة المسار الكامل. لا تبدأ Ubuntu Workspace قبل إنهاء Core. البنود D-06 وD-12 عُدّلت لتتوافق مع Lean Core.

---

## 0. قرارات مطلوبة قبل بدء التنفيذ

- [ ] **D-01 — الأجهزة المستهدفة:** تثبيت Adreno 730/750 أولًا، وتأجيل Mali.
  - القبول: مكتوب في `docs/decisions.md` مع الأجهزة المختبرة.
- [ ] **D-02 — root/chroot:** غير افتراضي، وضع متقدم صريح.
- [ ] **D-03 — Shizuku:** اختياري، capabilities محددة فقط.
- [ ] **D-04 — التوزيع:** sideload v1؛ لا Google Play مع `targetSdk 28`.
- [ ] **D-05 — الواجهة:** Kotlin/Compose؛ لا Flutter runtime في v1.
- [ ] **D-06 — سطح المكتب:** Openbox افتراضي في Core؛ XFCE حزمة Comfort؛ KDE لاحقًا.
- [ ] **D-07 — الألعاب:** Steam أولًا؛ Epic/GOG/محاكيات لاحقًا.
- [ ] **D-08 — الحد الأدنى:** `minSdk 28` تقنيًا؛ توصية Android 14+.
- [ ] **D-09 — الترخيص:** GPL compliance إلزامي؛ نشر المصدر المقابل.
- [ ] **D-10 — الاسم:** DeckOS مؤقتًا؛ قرار العلامة لاحقًا.
- [ ] **D-11 — الذكاء الاصطناعي:** مؤجل بعد MVP.
- [ ] **D-12 — حجم التنزيل:** Core ≤ 1GB بعد التثبيت؛ الحزم الكبيرة (Ubuntu/ألعاب) 3–5GB اختيارية وتنزيل تدريجي.

**بوابة:** لا يبدأ Sprint 1 قبل إغلاق D-01 إلى D-09 على الأقل.

## 1. Gate 0 — التأسيس (الأسبوع 1–2)

  - المحتوى: أصول، حدود ثقة، STRIDE، بيانات حساسة، أسوأ 10 سيناريوهات.
  - القبول: `docs/threat-model.md` مع mitigations.
  - التحقق: مراجعة أمنية داخلية.

- [ ] **G0-03 — Legal checklist**
  - المحتوى: GPL-3.0 (Termux/X11/DroidDesk/DroidDeck)، Apache-2.0 (Shizuku)، Steam/Proton، العلامات.
  - القبول: `docs/compliance.md` + قائمة ممنوعات التوزيع.
  - التحقق: لا distributable build قبل الإغلاق.

- [ ] **G0-04 — اختيار جهاز/أجهزة الاختبار**
  - المطلوب: S24 Ultra (Adreno 750)، Android 14؛ ويفضل جهاز Android 16/16 KB.
  - القبول: جدول أجهزة + حالة كل جهاز.
  - التحقق: `adb shell getprop` + `zcat /proc/config.gz` عند توفره.

- [ ] **G0-05 — مفتاح التوقيع وCI**
  - المطلوب: keystore خارج Git، متغيرات CI، `apksigner`، سياسة rotations.
  - القبول: build موقّع بـrelease key، وليس testkey.
  - التحقق: `apksigner verify --print-certs`.

- [ ] **G0-06 — هيكل المستودع**
  - المطلوب: وحدات `app/core/engines/bridge/runtime/bench/docs`.
  - القبول: Gradle build ناجح + lint + unit test فارغ.
  - التحقق: `./gradlew assembleDebug test lint`.

- [ ] **G0-07 — نظام التصميم وRTL**
  - المطلوب: tokens (لون/خط/مسافات/حركة)، مكونات أساسية، دعم RTL.
  - القبول: 5 شاشات mockup قابلة للتنفيذ.
  - التحقق: مراجعة بصرية + TalkBack labels.

- [ ] **G0-08 — منصة القياس**
  - المطلوب: سكربتات `bench/` + Perfetto + وسوم logcat.
  - القبول: تشغيل قياس واحد وإخراج JSON/CSV.
  - التحقق: تقرير عينة في `bench/results/`.

**بوابة Gate 0:** Spec + threat model + compliance + build موقّع + خط قياس جاهز.

## 4. Workspace — Ubuntu (الأسبوع 5–8)

- [ ] **W-01 — استيراد Ubuntu 22.04**
  - المطلوب: rootfs + proot + scripts + checksums.
  - القبول: إقلاع XFCE من داخل التطبيق.
  - التحقق: 3 مرات متتالية دون فشل.

- [ ] **W-02 — إصلاح GL**
  - المطلوب: إزالة `virgl` من `proot-fixes.sh`؛ llvmpipe افتراضيًا؛ Turnip/Zink تجريبي.
  - القبول: `glxinfo -B` يعمل؛ لا أخطاء GL حرجة.
  - التحقق: لوج + تشغيل Chromium.

- [ ] **W-03 — الصوت**
  - المطلوب: TCP 4713 أو AAudio؛ لا socket مفقود.
  - القبول: صوت من Chromium ومشغل وسائط.
  - التحقق: مقطع اختبار + `pactl info`.

- [ ] **W-04 — الإدخال العربي**
  - المطلوب: إزالة `GTK_IM_MODULE=ibus` أو تثبيت IBus؛ اختبار RTL.
  - القبول: كتابة عربية في Chromium/محرر.
  - التحقق: اختبار يدوي.

- [ ] **W-05 — sshd**
  - المطلوب: إصلاح أو تعطيل.
  - القبول: لا FATAL عند الإقلاع.
  - التحقق: `journalctl`/log.

- [ ] **W-06 — تقليم وتحديث**
  - المطلوب: Chromium حديث، Node واحد، حزم مكررة أقل، caches نظيفة.
  - القبول: خفض الحزم/القرص بنسبة موثقة.
  - التحقق: `dpkg -l`, `du`.

- [ ] **W-07 — تقليل الوصول**
  - المطلوب: إزالة `/data`؛ `/sdcard` عند الحاجة؛ SAF للملفات.
  - القبول: لا وصول لبيانات تطبيقات أخرى.
  - التحقق: اختبار من داخل الجلسة.

- [ ] **W-08 — الحافظة والإشعارات**
  - المطلوب: جسر X11 ↔ Android.
  - القبول: نسخ/لصق نص عربي وإنجليزي.
  - التحقق: اختبار ثنائي الاتجاه.

- [ ] **W-09 — ملفات تعريف 10 تطبيقات**
  - القائمة: Chromium، Files، Terminal، Text Editor، Image Viewer، PDF، Archive، Python، Node، code-server.
  - القبول: كل تطبيق يفتح من Launcher بملف تعريف.
  - التحقق: مصفوفة فتح/إغلاق.

**بوابة Workspace:** 10 تطبيقات تعمل، صوت/عربية/حافظة، لا P0، ولا `/data`.

## 9. Critical Path

```text
D-01..D-09 → G0-01..G0-06 → P-02..P-04 → W-01..W-03 → S-02..S-03 → Q-01..Q-06
```

- **P-02 (X11) وP-03 (طرفية) هما أكبر مخاطرة تقنية مبكرة.**
- **W-02/W-03 (GL/صوت) يحددان قابلية استخدام Ubuntu.**
- **S-03 (تنظيف العمليات) يحدد الاستقرار.**
- **Q-03 (أمان) بوابة توزيع.**
- **Shizuku وRouter يسيران بالتوازي بعد P-04، لا يعطّلان المسار الحرج.**

## 12. Definition of Done

كل مهمة تُغلق فقط عند:

- [ ] الكود/المكوّن موجود ويعمل.
- [ ] اختبار أو تحقق يدوي موثق.
- [ ] لا P0 جديدة.
- [ ] docs/قائمة المهام محدثة.
- [ ] قياس قبل/بعد إن كانت تؤثر على الأداء.
- [ ] مراجعة أمان إن كانت تلمس صلاحيات/تخزين/شبكة.
- [ ] لا أسرار في Git.
